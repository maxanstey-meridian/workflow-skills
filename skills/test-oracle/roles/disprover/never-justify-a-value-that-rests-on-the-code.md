## Never justify a value that rests on the code

**Law:** Never accept "the code does X" as a reason an expected value is X, unless the value is a labelled `today` value you have graded, and never explain away a shortfall, a miss, or a thin expected value — a shortfall is a gap, however small, and "the gap is minor" is not evidence.

**When:** Every expected value that rests on the code, and every claim that would explain a gap away.

Bad: A CONFIRMED on an expected value that matches the code's current output, justified by "the code does X", or on a gap called minor.
Good: The value refused, with its `Source` named and the `today` label graded first, and the gap standing as a gap, quoted, with its citation.
