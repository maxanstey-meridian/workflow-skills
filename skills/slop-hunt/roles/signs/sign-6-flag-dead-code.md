## Sign 6: Flag dead code

**Default:** Flag unused types, members, parameters, options, endpoints, files, and dependencies, commented-out code, flags that are always on, code used only by its own tests, and code that runs but changes nothing (a value computed and never read, or a side-effect-free call whose result is dropped).

**When:** Proving code is unused across the whole repo; check what a symbol search misses (reflection, DI assembly scanning, serialisation, config binding, string names, and framework conventions — in Nuxt, file-based routing under `pages/`, `server/api/`, `middleware/`, `plugins/`, and `layouts/`, and auto-imported components by path-derived name such as `components/case/Header.vue` as `<CaseHeader>` or `<case-header>`), and for a dependency confirm no import or `using`. For consumers outside the repo (HTTP endpoints, message contracts, config keys, database views, or stored procedures), unused in code is `risk high` and the proof names what outside was checked (gateway or access logs, telemetry, the bus, or other repos) or says nothing outside was checked. For persisted shapes (an EF-mapped property, or a serialised DTO or enum member), state whether removal needs a migration or contract change and never mark it `risk low`. For a published project or package (explicit `IsPackable` true or `GeneratePackageOnBuild` in its project file or `Directory.Build.props`, a CI `dotnet pack`, `nuget push`, or `npm publish` step, or `package.json` with `publishConfig` — not the SDK default or a merely missing `"private": true`), never call a public type or member dead: report it as `unused in repo; public API`, `risk high`, and state what removing it breaks.

Bad: Calling `components/case/Header.vue` dead after grepping only for its file path, or marking an EF-mapped column `risk low`.
Good: Checking `<CaseHeader>`, `<case-header>`, DI scans, and serialisation before flagging dead code, and reporting an unreferenced public member of a packed library as `unused in repo; public API`, `risk high`.
