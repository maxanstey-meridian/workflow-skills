## Classify each finding as fix, park, ask, or nit

**Law:** Set `do` to `fix` only when this work caused the harm, the spec promised it, or the fix is mechanical and a few lines with no design call and none of the `ask` cases holds; use `park` for real, non-trivial issues older than this work; before classifying a finding as `do: ask`, check the Meridian Laws (including `coding/make-valid-input-work-never-refuse-it.md`, `coding/fix-a-gap-never-document-it.md`, and never weakening a check), and if only one Law-compliant path exists and no genuine `ask` trigger holds, classify it `do: fix`; use `ask` only for genuine choices between Law-compliant working options, user-only questions, harms coming from a spec Decision itself rather than how it was built, fixes adding a mechanism neither the spec nor the code already has (a new type, mode, snapshot, cache, or second code path), or fixes changing what a Decision, Proof, or spec-quoted text says (listing only Law-compliant options on `fix`, with the option that promises less first — dropping or narrowing behaviour only when doing so does not break a Meridian Law, stating what users lose by it — and naming the Decision and any governing or broken Law rather than inventing a Law-breaking alternative such as refusing valid input or documenting a gap); and use `nit` for style only while leaving harmless code unflagged.

**When:** Assigning the `do:` line of every finding block in a slice review or doctrine review.

Bad: Marking a finding `do: fix` when fixing it requires introducing a new snapshot cache or changing a spec Decision, punting a bug as `do: ask` with "refuse valid input" as the narrower option when `coding/make-valid-input-work-never-refuse-it.md` settles the fix, or flagging harmless code as a `nit`.
Good: Marking a bug with only one Law-compliant fix `do: fix`, marking a spec-Decision harm `do: ask` with only Law-compliant options (narrowest compliant option first) while naming the Decision and governing Law, and leaving harmless code unflagged.
