## Make the headings read as the user's journey

**Default:** A setup flow's headings alone, read top to bottom, tell the user's journey in their terms, not the implementation's.

**When:** Setup flows and multi-step forms.

Bad: Headings "Create contract", "Select handler", "Resolve resource", "Configure expressions", "Set collision policy".
Good: Headings "Name this export", "Choose where it should send files", "Choose which data forms will provide", "Decide where and how files should be saved", "Review the resulting destination".
